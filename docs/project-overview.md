# 안동 여행 루트 추천 앱

## 프로젝트 개요

본 프로젝트는 사용자의 시간, 예산, 취향, 출발 시각을 바탕으로 안동 시내 여행 루트를 자동으로 추천하는 위치기반 여행 루트 추천 앱입니다.

초기 아이디어는 사용자의 취향, 위치, 예산, 이동수단, 여행 목적을 종합적으로 분석하여 AI가 최적의 여행 동선을 생성하는 플랫폼이었습니다.  
그러나 6월 8일 발표 일정과 팀원들의 개발 경험을 고려하여, 실제 상용 서비스 수준이 아닌 발표용 MVP 앱 프로토타입으로 구현 범위를 축소했습니다.

따라서 본 프로젝트의 핵심 목표는 실제 GPS, 실제 지도 API, 실시간 교통정보, 서버 DB, AI 학습 모델을 완성하는 것이 아니라, 정적 데이터와 모의지도를 활용하여 여행 루트 추천 과정과 알고리즘 동작 흐름을 시각적으로 보여주는 것입니다.

## 한 문장 주제

사용자의 시간·예산·취향·위치를 반영해 최적의 여행 동선을 자동 설계하고, 지역 명소 소비를 유도해 지역경제 활성화에도 기여하는 위치기반 맞춤형 여행 루트 플랫폼

## 프로젝트 목적

본 프로젝트는 안동 지역을 대상으로 사용자의 조건에 맞는 여행 장소를 추천하고, 추천된 장소들을 효율적인 순서로 연결하여 하나의 여행 루트로 제공하는 것을 목표로 합니다.

또한 단순히 장소 하나를 추천하는 것이 아니라, 여러 장소를 하나의 동선으로 묶어 사용자가 실제로 이동 가능한 여행 계획을 받을 수 있도록 합니다.

이를 통해 다음과 같은 효과를 기대합니다.

- 사용자의 여행 계획 수립 부담 감소
- 안동 지역 명소와 상권 노출 증가
- 지역경제 활성화 가능성 제시
- 알고리즘 기반 추천 시스템의 동작 방식 시연
- 발표 및 논문 작성에 활용 가능한 앱 프로토타입 제작

## 구현 대상 범위

본 프로젝트는 안동시 전체를 완전하게 다루는 서비스가 아니라, 발표 시연을 위해 제한된 범위의 장소와 이동 경로를 사용하는 모의 여행 루트 추천 앱입니다.

### 지역 범위

- 출발지: 경국대
- 여행 지역: 안동 시내
- 복귀지: 경국대

### 이동 흐름

```text
경국대
 → 110번 또는 210번 버스
 → 안동 시내 도착 정류장
 → 안동 시내 도보 여행 루트
 → 안동 시내 출발 정류장
 → 110번 또는 210번 버스
 → 경국대 복귀
```

### 장소 데이터

- 안동 시내 장소 약 20~25개
- 버스정류장 2개 이상
- 장소 간 연결 정보
- 정적 버스 시간표
- 장소별 태그, 비용, 체류시간, 영업시간, 좌표 정보

## 기존 계획과 최종 구현 방향

| 구분 | 초기 계획 | 최종 구현 방향 |
|---|---|---|
| 전체 방향 | AI 기반 여행 루트 플랫폼 | 발표용 모의지도 기반 앱 프로토타입 |
| 추천 방식 | 사용자 기록과 AI 학습 기반 추천 | 장소 태그와 조건을 이용한 룰기반 추천 |
| 지도 | 실제 지도 API 또는 내비게이션 연동 | 지도 이미지 위에 점과 선을 표시하는 모의지도 |
| 위치 기능 | 실시간 GPS 기반 LBS | 현재 위치 상태값을 이용한 위치 이동 시뮬레이션 |
| 교통 정보 | 실시간 교통 및 버스 상황 반영 | 정적 110/210 버스 시간표 사용 |
| 이동 방식 | 다양한 이동수단 고려 | 경국대↔안동 시내는 버스, 시내 내부는 도보 |
| 알고리즘 | 복잡한 최적화 및 AI 추천 | Greedy, Dijkstra, 룰기반 필터링 |
| 데이터 | 공공 API, 사용자 데이터, DB 활용 | 직접 입력한 정적 장소 데이터 사용 |
| 서버 | 서버 DB 및 사용자 계정 가능성 | 서버와 로그인 없이 로컬 데이터 기반 구현 |

## 주요 기능

### 1. 사용자 조건 입력

사용자는 여행 루트를 만들기 위해 다음 조건을 입력합니다.

- 여행 분위기
  - 먹거리탐방
  - 조용한
  - 전통문화
  - 자연
- 총 이용 가능 시간
- 예산
- 출발 시각
- 식사 여부 또는 여행 목적

이 입력값은 장소 추천과 루트 생성의 기준이 됩니다.

### 2. 장소 필터링

앱은 미리 입력된 장소 데이터에서 사용자의 조건에 맞는 장소를 필터링합니다.

예를 들어 사용자가 `먹거리탐방`을 선택하면 음식점, 시장, 카페와 같은 장소가 우선 추천됩니다.  
사용자가 `조용한` 분위기를 선택하면 박물관, 산책로, 북카페와 같은 장소가 우선 추천됩니다.

필터링 기준은 다음과 같습니다.

- 분위기 태그
- 카테고리
- 예상 비용
- 예상 체류시간
- 영업시간
- 사용자의 총 이용 가능 시간
- 사용자의 예산

### 3. 추천 점수 계산

각 장소는 사용자의 조건과 얼마나 잘 맞는지에 따라 추천 점수를 가집니다.

추천 점수에는 다음 요소를 반영합니다.

- 선택한 분위기와 장소 태그의 일치 여부
- 예산 조건 충족 여부
- 시간 조건 충족 여부
- 현재 위치와의 거리
- 식사 여부와 카테고리 적합성

이 방식은 실제 AI 학습 모델은 아니지만, 사용자의 취향과 조건을 반영한다는 점에서 룰기반 초개인화 큐레이션으로 설명할 수 있습니다.

### 4. 버스 시간표 적용

경국대에서 안동 시내로 진입할 때와, 안동 시내에서 경국대로 복귀할 때 110번 또는 210번 버스 시간표를 사용합니다.

버스 기능은 다음과 같이 구현합니다.

- 사용자가 입력한 출발 시각 이후 가장 가까운 버스 선택
- 경국대에서 안동 시내까지의 이동 시간 계산
- 안동 시내 여행 종료 후 복귀 가능한 버스 계산
- 실시간 지연, 결행, 교통 상황은 반영하지 않음

### 5. Greedy 알고리즘을 이용한 방문 순서 생성

장소 후보가 정해지면 Greedy 알고리즘을 사용하여 방문 순서를 결정합니다.

현재 위치에서 다음 장소를 고를 때 다음 기준을 고려합니다.

- 현재 위치에서 가까운 장소
- 추천 점수가 높은 장소
- 남은 시간 안에 방문 가능한 장소
- 예산을 초과하지 않는 장소

즉, 매 단계에서 현재 상황에서 가장 적절한 장소를 선택하는 방식입니다.

### 6. Dijkstra 알고리즘을 이용한 최단 경로 계산

장소와 장소 사이의 이동 경로는 모의지도 그래프를 기반으로 계산합니다.

각 장소는 노드로 표현하고, 장소 사이의 길은 간선으로 표현합니다.  
Dijkstra 알고리즘은 두 장소 사이에서 가장 짧은 경로를 계산하는 데 사용됩니다.

본 프로젝트에서는 실제 도로 데이터를 사용하지 않고, 직접 만든 모의지도 그래프를 사용합니다.

### 7. 모의지도 시각화

실제 지도 API를 사용하지 않고, 안동 시내를 표현한 지도 이미지 또는 단순화된 모의지도 위에 장소와 경로를 표시합니다.

모의지도에는 다음 요소가 포함됩니다.

- 장소 위치 점 표시
- 장소 이름 표시
- 장소 간 연결선 표시
- 추천 루트 강조
- 현재 위치 표시
- 방문 완료 장소 표시
- 다음 장소 이동 버튼
- 경로 재추천 버튼

### 8. 다음 장소 이동 및 재추천

사용자가 `다음 장소로 이동` 버튼을 누르면 현재 위치가 다음 장소로 변경됩니다.

방문한 장소는 완료 처리되고, 남은 장소를 기준으로 현재 위치에서 다시 경로를 계산할 수 있습니다.

재추천 기능은 시간이 부족할 경우 선택 기능으로 구현합니다.

## 핵심 기술 개념

| 기술 | 프로젝트 내 역할 | 실제 구현 방식 |
|---|---|---|
| 룰기반 추천 | 사용자 조건에 맞는 장소 선택 | 태그, 예산, 시간, 카테고리 기반 필터링 |
| Greedy | 방문 순서 결정 | 현재 위치에서 가장 적절한 다음 장소 선택 |
| Dijkstra | 장소 간 최단 경로 계산 | 모의지도 그래프에서 최단 거리 계산 |
| LBS | 위치 기반 서비스 개념 표현 | 실제 GPS 대신 현재 위치 상태값으로 시뮬레이션 |
| 버스 시간표 | 경국대↔안동 시내 이동 계산 | 정적 110/210 버스 시간표 사용 |
| 모의지도 | 경로 시각화 | 지도 이미지 위에 장소 점과 선 표시 |

## 데이터 구성

데이터 담당자는 장소와 버스 정보를 정적 파일에 입력합니다.

### 장소 데이터

장소 데이터에는 다음 정보가 포함됩니다.

- 장소 ID
- 장소 이름
- 카테고리
- 분위기 태그
- 예상 비용
- 예상 체류시간
- 영업시간
- 좌표값
- 설명
- 추천 이유

예시:

```ts
{
  id: "place_001",
  name: "안동 구시장",
  category: "food",
  tags: ["먹거리탐방", "전통문화"],
  cost: 10000,
  stayTime: 60,
  openTime: "10:00",
  closeTime: "21:00",
  x: 120,
  y: 250,
  description: "안동의 대표적인 먹거리와 시장 분위기를 경험할 수 있는 장소"
}
```

### 버스 데이터

버스 데이터에는 다음 정보가 포함됩니다.

- 버스 번호
- 출발 정류장
- 도착 정류장
- 출발 시각
- 예상 이동 시간

예시:

```ts
{
  busNumber: "210",
  from: "경국대",
  to: "안동시내",
  departureTime: "09:30",
  duration: 25
}
```

### 장소 간 연결 데이터

장소와 장소 사이의 연결 정보는 Dijkstra 알고리즘에 사용됩니다.

예시:

```ts
{
  from: "place_001",
  to: "place_002",
  distance: 450,
  walkTime: 6
}
```

## GitHub 협업 방식

팀원들이 같은 파일을 동시에 수정하면 충돌이 발생할 수 있으므로, 역할별로 수정 파일을 나누어 관리합니다.

기본 원칙은 다음과 같습니다.

- 팀장은 전체 구조와 화면 연결을 관리합니다.
- 데이터 담당자는 `src/data/` 폴더만 주로 수정합니다.
- UI 담당자는 `src/components/` 폴더를 주로 수정합니다.
- 알고리즘 담당자는 `src/algorithms/` 폴더를 주로 수정합니다.
- 수정 전에는 항상 최신 파일을 확인합니다.
- 수정 후에는 Commit 메시지를 작성하고 Pull Request로 검토를 요청합니다.
- 큰 논의는 Discussions, 실제 수정 요청은 Issues, 코드 반영은 Pull Request를 사용합니다.

본 프로젝트에서는 다음 기능을 구현하지 않습니다.

## 발표 시 설명 주의사항

발표에서는 구현하지 않은 기능을 완성했다고 말하지 않습니다.

다음과 같이 표현합니다.

- 실시간 GPS 구현  
  → LBS 개념을 반영한 모의 위치 안내 기능

- 실제 AI 학습 모델  
  → 사용자 조건과 장소 태그를 활용한 룰기반 초개인화 큐레이션

- 실제 지도 API 연동  
  → 지도 이미지와 그래프 구조를 활용한 모의지도 시각화

- 실시간 버스 정보 반영  
  → 정적 110/210 버스 시간표 기반 진입 및 복귀 계산

## 최종 정리

이 프로젝트는 안동 여행 루트 추천 서비스를 실제 상용 서비스 수준으로 완성하는 것이 아니라, 핵심 아이디어와 알고리즘 흐름을 발표에서 보여주기 위한 MVP 앱 프로토타입입니다.

사용자가 분위기, 시간, 예산, 출발 시각을 입력하면 앱은 정적 장소 데이터와 버스 시간표를 기반으로 장소를 추천하고, Greedy와 Dijkstra 알고리즘을 활용하여 추천 루트를 생성합니다.

최종적으로 모의지도 위에 장소와 이동 경로를 표시하여, 사용자가 어떤 순서로 안동 시내를 여행하면 되는지 시각적으로 확인할 수 있도록 합니다.
