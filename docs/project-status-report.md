# 안동 여행 루트 추천 앱 팀원 배포용 프로젝트 현황 보고서

> 데이터 정합성 · 알고리즘 구현 현황 · UI 미구현 항목 · 우선 수정 과제 정리

**전체 진행도: 68%**

## 핵심 결론

현재 프로젝트는 기획, 문서, 데이터, 알고리즘 기반이 상당 부분 갖춰져 있으나, 발표에서 가장 눈에 보이는 **모의지도 UI**와 **경로 요약 화면**이 미구현 상태이다. 데이터는 25개 장소로 구성되어 있으나 일부 장소의 `nearestBusStopId` 값 수정이 필요하다.

## 2. 프로젝트 개요

프로젝트는 안동 옥동 지역을 중심으로 사용자의 여행 조건을 입력받아 추천 루트를 생성하는 Expo/React Native 기반 앱이다. 사용 조건으로 출발 시각, 이용 가능 시간, 선호 카테고리, 선호 테마, 식사 여부, 최대 방문 장소 수를 받고, 장소 데이터와 버스 시간표를 반영하여 추천 경로를 출력하는 구조이다.

| 항목 | 내용 |
|---|---|
| 프로젝트 유형 | 위치 기반 여행 루트 추천 앱 MVP |
| 중심 지역 | 안동 옥동 상권 중심 |
| 주요 사용자 시나리오 | 경국대 또는 안동 주요 정류장에서 출발하여 옥동 내 추천 장소 방문 |
| 핵심 기능 | 사용자 조건 입력, 장소 필터링, 점수 기반 추천, 버스 이동 계산, 추천 루트 출력 |
| 시각화 방향 | 실제 지도 API 대신 모의지도 위 마커와 경로선 표시 |

## 3. 현재 진행도 종합

현재 프로젝트의 전체 진행도는 약 **68%**로 평가된다. 문서와 데이터, 알고리즘 기반은 마련되어 있으나 UI 시각화 영역이 미완성 상태이므로 발표 완성도 측면에서 보완이 필요하다.

| 영역 | 진행도 | 평가 요약 |
|---|---:|---|
| 기획/문서 | 90% | 프로젝트 개요, 데이터/알고리즘/UI/통합 가이드북이 정리되어 있음 |
| 데이터 | 82% | 장소 25개, 정류장 11개, 시간표 24구간 존재. 일부 `nearestBusStopId` 수정 필요 |
| 알고리즘 | 75% | 점수 계산, Greedy 루트 생성, 버스 시간 탐색, 총 시간 계산 구현 |
| UI | 38% | 테스트 UI는 있으나 `MockMapView.tsx`와 `RouteSummary.tsx`가 0 bytes |
| 통합 | 65% | `index.tsx`에서 데이터와 알고리즘 호출은 가능하나 발표용 화면 구성 미완성 |
| 전체 | 68% | 발표 가능한 구조는 있으나 시각화와 데이터 정합성 수정 필요 |

> 현재 프로젝트는 “작동 구조는 있으나 보여주는 화면이 부족한 상태”로 분류된다. 신규 기능 확장보다 데이터 정합성 수정, 타입 오류 수정, 모의지도 UI 구현이 우선이다.

## 4. 데이터 파트 현황

현재 `places.ts`에는 총 25개의 장소 데이터가 존재하며, `busStop.ts`에는 총 11개의 버스정류장 데이터가 존재한다. `busSchedules.ts`에는 110번과 210번 노선의 방향별 구간 및 09:00~22:00 사이 20분 간격 출발 시간이 구성되어 있다.

| 데이터 항목 | 현재 상태 | 평가 |
|---|---|---|
| 장소 데이터 | 25개 | 목표 범위 충족 |
| 버스정류장 데이터 | 11개 | 110번·210번 노선 정류장 포함 |
| 버스 시간표 | 24개 방향 구간 | 상행/하행 방향 구조 존재 |
| 장소 좌표 | 위도/경도 입력 | 모의지도 좌표 변환 가능 |
| 카테고리/테마 | 비트마스크 방식 | 알고리즘 처리에 적합 |
| 장소 설명/체류시간 | 입력 완료 | 결과 화면 표시 가능 |

### 4-1. 동떨어진 4개 장소 교체 반영 상태

이전 데이터 구성에서는 월영교, 안동구시장, 안동시립박물관, 문화의 거리처럼 옥동 중심 모의지도에 넣기 어려운 장소가 포함되어 있었다. 현재 ZIP 기준 `places.ts`에는 해당 4개 장소가 포함되어 있지 않으며, 스타벅스 안동옥동점, 이디야커피 안동옥동점, 옥동 제3공원, 옥동 중앙공원, 메가박스 안동점 등 옥동 중심 장소로 재구성되어 있다.

| 이전 문제 항목 | 문제점 | 현재 상태 |
|---|---|---|
| 월영교 | 옥동 중심 모의지도에서 거리 차이가 큼 | 현재 `places.ts`에 없음 |
| 안동구시장 | 옥동 상권과 분포가 다름 | 현재 `places.ts`에 없음 |
| 안동시립박물관 | 옥동 기준 화면 구성 난이도 증가 | 현재 `places.ts`에 없음 |
| 문화의 거리 | 옥동 상권과 지도 범위가 다름 | 현재 `places.ts`에 없음 |

> 동떨어진 4개 장소 문제는 현재 ZIP 기준으로 대부분 해결된 상태이다. 남은 데이터 문제는 장소 개수가 아니라 장소와 정류장 연결값의 정합성이다.

### 4-2. `nearestBusStopId` 수정 필요 항목

`nearestBusStopId`는 장소에서 가장 가까운 버스정류장을 연결하는 값이다. 버스가 해당 방향으로 이동 가능한지는 `busSchedules.ts`와 알고리즘에서 판단하므로, `nearestBusStopId` 자체는 “장소 기준 최단거리 정류장”을 우선 기준으로 삼는 것이 적절하다.

현재 일부 옥동 장소가 교보생명, 신시장, 구 안동역 등 거리상 멀리 있는 정류장으로 연결되어 있다. 아래 항목은 옥동농협앞(`id: 4`)으로 수정하는 것이 적절한 장소이다.

| 장소 | 현재 연결 | 권장 연결 | 권장 정류장까지 거리 |
|---|---|---|---:|
| 컴포즈커피 옥동점 | 3 교보생명 | 4 옥동농협앞 | 약 246m |
| 교촌치킨 옥동점 | 3 교보생명 | 4 옥동농협앞 | 약 202m |
| BBQ치킨 옥동점 | 3 교보생명 | 4 옥동농협앞 | 약 229m |
| 맘스터치 안동옥동점 | 3 교보생명 | 4 옥동농협앞 | 약 209m |
| 다이소 안동옥동점 | 3 교보생명 | 4 옥동농협앞 | 약 179m |
| 옥동 중앙공원 | 2 신시장 | 4 옥동농협앞 | 약 352m |
| GS25 옥동중앙점 | 3 교보생명 | 4 옥동농협앞 | 약 188m |
| CU 옥동한빛점 | 2 신시장 | 4 옥동농협앞 | 약 294m |
| 메가박스 안동점 | 5 구 안동역 | 4 옥동농협앞 | 약 50m |
| 바디핏 헬스장 옥동점 | 3 교보생명 | 4 옥동농협앞 | 약 283m |

수정 예시:

```ts
nearestBusStopId: 4 // 옥동농협앞
```

## 5. 버스 진행방향 처리 현황

버스 진행방향은 데이터 구조상 어느 정도 반영되어 있다. `busSchedules.ts`에는 110번 하행과 상행, 210번 하행과 상행이 각각 방향성 있는 구간으로 분리되어 있다.

| 노선 | 방향 | 정류장 흐름 |
|---|---|---|
| 110번 | 하행 | 안동역(안동터미널) → 옥동농협앞 → 신시장 → 교보생명 → 구 안동역 → 용상시장 → 국립경국대 |
| 110번 | 상행 | 국립경국대 → 용상시장 → 구 안동역 → 교보생명 → 신시장 → 옥동농협앞 → 안동역(안동터미널) |
| 210번 | 하행 | 교보생명 → 신시장 → 안동역(안동터미널) → 안동과학대학교 → 풍산정류장 → 하회마을 → 병산서원 |
| 210번 | 상행 | 병산서원 → 하회마을 → 풍산정류장 → 안동과학대학교 → 안동역(안동터미널) → 신시장 → 교보생명 |

> 버스 진행방향 데이터는 존재한다. 그러나 `nearestBusStopId`는 진행방향이 아니라 장소 기준 가장 가까운 정류장을 의미한다. 현재 수정 대상은 버스 방향 로직이 아니라 장소-정류장 연결 데이터이다.

## 6. 알고리즘 파트 현황

알고리즘 파트는 단순 예시 수준을 넘어서 실제 데이터와 연결되는 핵심 함수들이 구현되어 있다. `createRoute()`를 통해 사용자 입력을 받고, 장소 점수 계산, Greedy 경로 생성, 이동 시간 계산, 버스 탐색을 수행하는 구조이다.

| 파일 | 역할 | 현황 |
|---|---|---|
| `routeMaker.ts` | 전체 루트 생성 흐름 통합 | 구현됨 |
| `greedyRoute.ts` | 방문 장소 선택 | 구현됨 |
| `scoreCalculator.ts` | 카테고리·테마·거리 기반 점수 계산 | 구현됨 |
| `busTimeCalculator.ts` | 버스 시간 탐색 및 대기시간 계산 | 구현됨 |
| `routeTimeCalculator.ts` | 총 소요시간 계산 | 구현됨 |
| `distanceUtils.ts` | 위도/경도 거리 계산 | 구현됨 |
| `timeUtils.ts` | 거리 기반 도보 시간 계산 | 구현됨 |

주의할 점은 문서상 Dijkstra가 언급되어 있으나, 현재 코드에는 별도의 `dijkstra.ts` 또는 명확한 그래프 기반 최단경로 구현 파일이 확인되지 않는다는 점이다. 발표 자료에서는 실제 구현 범위와 문서 설명이 어긋나지 않도록 표현을 조정해야 한다.

## 7. UI 파트 현황

UI 파트는 현재 프로젝트의 가장 큰 미완성 영역이다. `app/(tabs)/index.tsx`에는 테스트용 입력 및 결과 출력 화면이 구성되어 있어 알고리즘 실행 흐름은 확인 가능하다. 그러나 발표에서 핵심적으로 보여야 하는 모의지도와 경로 요약 컴포넌트가 아직 구현되지 않았다.

| UI 항목 | 현재 상태 | 비고 |
|---|---|---|
| 사용자 조건 입력 | 일부 구현 | `index.tsx` 테스트 UI에서 선택 가능 |
| 알고리즘 실행 버튼 | 구현 | `createRoute()` 호출 가능 |
| 결과 텍스트 출력 | 일부 구현 | 디버그/테스트 성격 |
| `PlaceCard.tsx` | 수정 필요 | 현재 `Place` 타입과 맞지 않는 필드 사용 |
| `MockMapView.tsx` | 미구현 | 0 bytes |
| `RouteSummary.tsx` | 미구현 | 0 bytes |
| 발표용 화면 흐름 | 미완성 | 입력 → 지도 → 상세 요약 흐름 정리 필요 |

### 7-1. `PlaceCard.tsx` 타입 오류

현재 `PlaceCard.tsx`는 이전 데이터 타입 기준 필드를 사용하고 있다. 현재 `Place` 타입에는 `category`, `moodTags`, `avgCost`, `stayMinutes`가 존재하지 않으므로 빌드 오류 또는 런타임 오류가 발생할 수 있다.

| 현재 사용 필드 | 문제 | 대체 필드 |
|---|---|---|
| `place.category` | 현재 `Place` 타입에 없음 | `place.categories` |
| `place.moodTags` | 현재 `Place` 타입에 없음 | `place.themes` |
| `place.avgCost` | 현재 `Place` 타입에 없음 | 필요 시 데이터 타입에 비용 필드 추가 또는 표시 제거 |
| `place.stayMinutes` | 현재 `Place` 타입에 없음 | `place.averageTime` |

현재 `Place` 타입:

```ts
export type Place = {
  id: number;
  name: string;
  categories: number;
  themes: number;
  averageTime: number;
  latitude: number;
  longitude: number;
  nearestBusStopId: number;
  description: string;
};
```

## 8. 우선 수정 과제

남은 작업은 새로운 기능 추가보다 현재 구현된 구조의 정합성을 맞추고, 발표에서 보이는 화면을 완성하는 방향으로 진행하는 것이 적절하다.

| 우선순위 | 작업 | 담당 파트 | 목적 |

| 4 | `RouteSummary.tsx` 구현 | UI | 총 시간, 방문 장소, 버스/도보 요약 표시 |
| 5 | 발표용 입력 시나리오 고정 | 통합/발표 | 시연 안정성 확보 |
| 6 | 문서와 실제 구현 범위 표현 정리 | 문서/발표 | Dijkstra 등 미구현 표현 과장 방지 |

## 10. 최종 평가

현재 프로젝트는 기획과 문서, 데이터, 알고리즘의 기반은 확보되어 있으나, 발표 완성도에 직접 영향을 주는 UI 시각화가 부족한 상태이다. 동떨어진 장소 데이터 문제는 현재 ZIP 기준으로 해결된 상태에 가깝고, 남은 핵심 데이터 문제는 `nearestBusStopId` 정합성이다.

- 전체 진행도는 약 **68%**로 평가된다.
- 데이터는 장소 25개 기준을 충족했으나, 10개 장소의 정류장 연결값 수정이 필요하다.
- 버스 진행방향 데이터는 존재하며, 현재 문제는 버스 방향이 아니라 장소-정류장 연결값이다.
- 알고리즘은 실제 데이터와 연결되어 있으나, Dijkstra 구현 여부는 문서 표현과 맞춰야 한다.
- UI는 테스트 화면 수준이며, `MockMapView.tsx`와 `RouteSummary.tsx` 구현이 핵심 과제이다.

## 최종 결론

현재 단계에서 가장 중요한 작업은 **데이터 정합성 수정**과 **모의지도 UI 구현**이다. 장소 추가나 기능 확장보다 `nearestBusStopId` 수정, `PlaceCard` 타입 오류 해결, `MockMapView` 및 `RouteSummary` 구현을 우선 처리해야 한다.
